## 5. Модель данных и распределение ответственности

Задача описывается объектом `{ id, title, completed, priority }`, где:

- `id` — положительное безопасное целое, не совпадает с индексом в массиве;
- `title` — строка от 1 до 100 символов после `trim()` (внутренние пробелы сохраняются);
- `completed` — строго `boolean`;
- `priority` — один из `low | medium | high`, по умолчанию `medium`.

Ответственность разнесена по модулям:

- `src/data.js` — исходные данные: общий набор `demoTasks` и набор варианта `variantTasks`;
- `src/task-service.js` — чистая логика: проверки входных данных и операции, возвращающие либо `{ ok: true, ... }`, либо `{ ok: false, error: "..." }`;
- `src/main.js` — сценарии и вывод, только здесь разрешены `console.*`;
- `src/task-extra.js` — расширение (поиск по названию).

Все операции возвращают **новый массив** и не изменяют ни переданные задачи, ни исходные массивы.

Начальные данные — `demoTasks` (4 задачи). Вывод по каждому шагу получается через деструктуризацию результата `getTaskStats`: `const { total, completed, pending, progress } = ...`.

После шага 5 в наборе остались задачи с id `[1, 4, 10, 20]`; единственная невыполненная — `id=20`.

Обработанные ошибки (состояние после них не меняется):

- повторное добавление `id=4` → «Задача с таким id уже существует»;
- неверный статус `"true"` (строка) → «Не верный тип данных»;
- удаление отсутствующего `id=777` → «Задача не найдена»;
- пустое название при переименовании → «Длина названия от 1 до 100 символов».

В конце сценария `demoTasks` повторно выводится и остаётся в исходном виде (проверяется и в `checks.js`).

## 9. Расширение

Вариант А: функция `searchTasks(tasks, query)` в `src/task-extra.js`. Запрос обрезается от краевых пробелов, сравнение идёт по подстроке названия **без учёта регистра**. Возвращается `{ ok: true, tasks }` с новым массивом найденных задач либо `{ ok: false, error }` для нестрокового/пустого/слишком длинного запроса.

Пример из `main.js`:

- `searchTasks(current, "подготовить")` → [`id=11`, `id=41`, `id=64`, `id=80`];
- `searchTasks(current, 123)` → `{ ok: false, error: "Запрос должен быть строкой" }`.

## 10. Вывод

В ходе работы реализованы чистые функции для работы со списком задач: создание, поиск по id, выборка невыполненных, названия, статистика и операции изменения (добавление, статус, переименование, удаление). Ключевые принципы: входные данные никогда не изменяются (spread, map, filter), проверки вынесены в `createTask` и переиспользуются при добавлении/переименовании, ошибки передаются через `{ ok: false, error }` вместо исключений. Эксперименты наглядно показали разницу между значением и ссылкой: копирование массива не копирует вложенные объекты, а порядок свойств в `{ ... }` влияет на результат. На основе модуля выполнен общий сценарий и сценарий варианта 4; все 38 проверок (35 основных и 3 собственных) проходят без ошибок.
