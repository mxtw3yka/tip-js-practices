## Эксперименты с формой и хранилищем

| № | До запуска: прогноз | После запуска: результат | Объяснение |
|---:|---|---|---|
| 1. Пустое обязательное поле | Браузер не позволит отправить форму | `submit` не возник: журнал «Действия ещё не выполнялись», `validity.valid = false`, `valueMissing = true`, стандартное сообщение «Please fill out this field.», запись в `localStorage` отсутствует | Поле `required`: нативная проверка выполняется до события `submit` |
| 2. Название из пробелов | Нативная проверка его пропустит, прикладная — отклонит | Нативно `valid = true` (строка непустая), обработчик `submit` вызван, после `setCustomValidity` — `customError = true`, сообщение «Название не должно состоять только из пробелов.», запись не создана | Пробелы проходят HTML5-проверку, поэтому «пустоту» проверяет прикладной код после обрезания |
| 3. Типы значений `FormData` | Все значения — строки | `typeof title === "string"`, `typeof priority === "string"`; поле «id» в демо-форме не имеет `name`, поэтому `FormData.get("id") === null`; `submit.defaultPrevented = true`: обработчик отменил стандартное действие; введено «  Тест формы  », сохранено «Тест формы» (пробелы обрезаны); `typeof localStorage.getItem === "string"` | `FormData` всегда возвращает строки; значения в хранилище — тоже строки (JSON) |
| 4. Строка в `localStorage` и JSON | В хранилище лежит строка, которую нужно разобрать | `raw` — строка `{"title":"Тест формы","priority":"high"}`; после `JSON.parse` — объект с теми же полями | `localStorage` хранит только строки; структура восстанавливается через `JSON.parse` |
| 5. Повреждённый JSON | `JSON.parse` упадёт, нужно показать диагностику | Ошибка `Expected property name or '}' in JSON at position 1 (line 1 column 2)`; приложение продолжает работать и использует исходный набор с предупреждением | Любые данные из хранилища — пользовательские, поэтому всегда проверяются до использования |

## Организация кода

- `task-service.js` — чистая предметная логика над массивом задач: `createTask`, `addTask`,
  `setTaskCompleted`, `renameTask`, `updateTask`, `deleteTask`, `findTaskById`, фильтры и сводка.
  Ни одна функция не обращается к DOM и к хранилищу.
- `form-validation.js` — чистая функция `validateTaskDraft(draft, tasks, editingId)`.
  Нормализует поля (id → число, название → обрезка пробелов), проверяет границы
  (длина 1…100, допустимые приоритеты) и уникальность id, учитывая режим редактирования.
  Возвращает `{ ok }` или `{ ok: false, errors }`.
- `task-storage.js` — хранение в виде строки JSON с версией:
  `{ "version": 1, "tasks": [...] }`. `loadTasks(storage, key, fallback)`, `saveTasks(...)`,
  `removeSavedTasks(...)` и проверка `isValidTaskList`.
- `task-view.js` — только создание DOM: карточка с кнопками toggle/edit/delete,
  фильтры, сводка. Обработчиками событий не занимается.
- `main.js` — связывает модули: инициализация набора (demo или вариант), форма
  (создание/редактирование), делегирование кликов и клавиш, сохранение, сброс,
  восстановление, расширение «две вкладки» (событие `storage`).

Функции хранения принимают объект `storage` аргументом, а не используют
`window.localStorage` напрямую: это делает модуль тестируемым в изоляции
(подмена объекта в проверках), а в основном коде хранилище можно заменить
без изменения логики. Данные из JSON проверяются до использования, потому что
`localStorage` — это внешние пользовательские данные: они могут быть пустыми,
повреждёнными или содержать неверную схему, и их нельзя доверять без проверки.

Минимум один случай относится к границе формы (№ 1), один — к восстановлению
после перезагрузки (№ 2), один — к повреждённым или недоступным данным хранилища (№ 3).

## Отладка и клавиатура

В `handleFormSubmit` (src/main.js) установлены точки останова после вызова
`validateTaskDraft` (строка 186), после сервисной операции (строка 202) и после
`saveTasks` в `persistCurrentTasks` (строка 161).

Успешное добавление `id = 80`:

- сырой `draft` из `FormData`: `{"id":"80","title":"  Отладочная задача  ","priority":"high"}` (id и значения — строки, пробелы на месте);
- результат `validateTaskDraft`: `{"ok":true,"value":{"id":80,"title":"Отладочная задача","priority":"high"}}` (id → число, пробелы обрезаны);
- результат `addTask`: `{"ok":true,"tasks":[<4 исходных задачи>, {"id":80,...}]}`;
- после `saveTasks` строка в `localStorage`: `{"version":1,"tasks":[...]}` — JSON с версией.

Повторный `id = 4`:

- `draft`: `{"id":"4","title":"Дубликат","priority":"low"}`;
- `validateTaskDraft` → `{"ok":false,"errors":{"id":"Задача с таким идентификатором уже существует."}}` — сервис не вызван, `saveTasks` не происходит.

Клавиатура (проверено через реальные нажатия Tab/Enter/Space):

- порядок Tab в форме: id → название → приоритет → «Добавить задачу», далее фильтры;
- Enter в поле названия отправляет форму (задача добавлена, форма очищена);
- в карточках Tab доходит до кнопки toggle, Space переключает статус
  (`aria-pressed` `true → false`);
- Enter на кнопке «Изменить» открывает редактирование: фокус переходит в поле названия,
  поле id становится недоступным;
- Enter на кнопке «Отменить» возвращает режим создания: поле id доступно и пустое,
  фокус устанавливается на поле id (см. `setFormMode`: при начале создания фокус на id,
  при начале редактирования — на название).

## Дополнительное задание

Выполнено расширение «Вариант Б»: синхронизация двух вкладок через событие `storage`
(реализовано в `main.js`, слушатель `storage`).

Правила:

- вкладка слушает событие `storage` только для ключа текущего набора
  (`event.key === storageKey`), чтобы не реагировать на чужие данные;
- при изменении из другой вкладки выполняется `loadTasks` и перерисовка списка
  с сообщением «Список обновлён по событию storage из другой вкладки.»;
- состояние формы (режим создания/редактирования, введённый текст) в активной
  вкладке не перезаписывается: обновляются только задачи;
- если запись из другой вкладки повреждена, используется прежний список
  с предупреждением.

Проверки (две вкладки A и B на одной странице):

1. Р1 — в A добавлена задача `id = 70`: в B без перезагрузки появилась задача,
   сводка 40.0%, статус «Данные обновлены из другой вкладки.».
2. Р2 — в A нажат сброс: в B список вернулся к `[1,4,7,10]`, статус
   «Сохранённые данные удалены в другой вкладке; используется исходный набор.».
3. Р3 — в A в хранилище записан `{broken-json`: в B список не изменился,
   выведено предупреждение об ошибке JSON, форма продолжает работать.
4. Р5 — B редактирует id = 4, A переключает статус id = 7: список в B обновился,
   режим редактирования и введённый текст сохранены (id остается недоступным).
5. Р6 — A удаляет id = 4, который редактирует B: B переходит в режим создания,
   поле id снова доступно (защита от редактирования отсутствующей задачи).
6. Р7 — запись из B видна в A: добавив id = 72 в B, в A список обновился, сводка 40.0%.

- прикладная валидация (`validateTaskDraft`) нормализует и проверяет значения уже

- проверка данных после чтения из хранилища (`isValidTaskList`) нужна, потому что
  данные в `localStorage` — внешние: повреждённый JSON, неверная схема или
  недоступное хранилище не должны ломать запуск приложения.
